## 단계별 상세 내역 (증빙 가능한 사실 기준)

### ① 아이디어 발굴
- **도구:** Claude (claude.ai 대화형)
- **내용:** '브랜드 단위 상관·집중 리스크'라는 프레임 정교화, 2025년 입상작과의 차별점 분석,
  평가기준 6개 항목별 득점 전략 수립, 기획서(FranSCORE_기획서_최종본.md) 공동 작성.
- **인간 기여:** 문제 인식(프랜차이즈 폐업 급증·자영업 대출 부실)과 주제 선정은 팀이 주도.

### ② 정보수집
- **도구:** Claude Code (모델: Claude Fable 5 / Claude Opus 5) — 병렬 웹 리서치 에이전트 9기(2차례)
- **내용:**
  - 1차: 공정위 오픈API 명세 조사(엔드포인트·파라미터·응답필드·인증방식·커버리지 실측),
    키 없는 파일데이터 대안 전수조사, franchise.ftc.go.kr 접근 메커니즘,
    뉴스 소스(Google News RSS·네이버 API) 비교 검증
  - 2차(빈틈 보강): 명세가 요구한 **직영점수·브랜드×지역 분포·브랜드 관리번호**의
    실제 제공 API를 라이브 호출로 확정 — 15125490·15125467·15125518 발굴 및 응답 필드 실측,
    가명·구간값 데이터셋(15143710/15143709) 배제 근거 확보,
    15125569 정보공개서가 별도 키를 요구함을 7가지 변형 호출로 확인
- **증빙:** 조사 결과가 `src/collect.py` SERVICES 정의·주석과 README 데이터 출처표에 반영됨.
  독립 API 간 가맹점수 일치율 98.9%로 조인 정합성 교차검증.

### ③ 데이터 분석
- **도구:** Claude Code (모델: Claude Fable 5) + LightGBM·SHAP·scikit-learn
- **내용:**
  - 공정위 오픈API 7종 실데이터 수집·정합·패널화 (브랜드×연도 패널 + 브랜드×연도×지역 144만행)
  - 엔티티 정합 규칙 설계(브랜드명 정규화·동명 분리·본부변경 추적), 생존성 진단
  - '악화 전환' 라벨 설계·검증(자격 표본 양성률 9.2%, 시점누출 자동 테스트), 완전 시간분할
    백테스트 + 확장창 워크포워드, 기준모형 3종 대비 성능 비교, 확률 보정, SHAP 요인 분해,
    포트폴리오 상관손실 시나리오
- **증빙:** `outputs/` 지표 산출물 전체, `tests/test_sanity.py`.

### ④ 코드작성 및 디버깅
- **도구:** Claude Code (모델: Claude Fable 5 / Claude Opus 5; 멀티에이전트 병렬 구현·리뷰 워크플로)
- **내용:**
  - 전체 코드베이스(`src/` 15개 모듈, `run_pipeline.py`, `run_both_tracks.py`, `check_keys.py`,
    `tools/check_doc_numbers.py`, `tests/` 2종, Streamlit 대시보드) 작성
  - 모듈 간 인터페이스 계약서(`docs/INTERFACES.md`) 기반 병렬 개발 + 자가 테스트
  - **적대적 코드리뷰 워크플로**를 2차례 운영. 여러 에이전트가 서로 다른 차원(누출·정합·
    평가·LLM·문서)을 나눠 탐색하고, 발견 건마다 **별도 검증 에이전트가 "결함이 아님"을
    입증하도록**(refute-by-default) 시켜 재현되지 않는 지적은 기각했다.
    - 1차 확정 7건: 표본 선별 룩어헤드, 미검증 '양호' 라벨, logloss 조기종료,
      보정확률 동률 붕괴, 대시보드 스트레스 방향 반전, 등급 컷 왜곡, 0점포 유령 라벨
    - 2차 확정 11건: RAG 매출 단위 10배 오류, 폴백 조인 오귀속, 누출 테스트 커버리지 공백,
      ablation 복잡도 불일치, 문서 낡은 수치 등
  - 그 뒤 **자동 검사가 사람보다 먼저 잡은 결함**도 있다: 시점누출 테스트가 "피처 스키마가
    미래 값에 의존"함을 검출했고(상수컬럼 사후 제거 방식의 부작용), 워크포워드 집계에서
    **풀링 Lift가 모든 개별 fold보다 낮은 모순**을 발견해 원인(fold별 확률 스케일 드리프트)을
    규명하고 집계 방식을 수정했다 — 결함을 감추지 않고 진단표까지 산출물로 공개한다.
- **비고 (개발 도구 AI ≠ 산출물 내부 AI — 구분해서 읽어주십시오):**
  - **개발에 사용한 AI**는 위 표대로 Claude Code(Claude Fable 5 / Opus 5)다.
  - **산출물 자체에 런타임 구성요소로 탑재된 LLM**은 **Google Gemini
    (`gemini-2.5-flash`, Generative Language API v1beta)** 다 — 뉴스 신호 구조화 추출과
    심사메모 생성에 실제로 호출된다(`src/llm.py` 공용 클라이언트, 실키로 라이브 검증 완료).
  - LLM 층은 **폴백 우선 설계**다. 키 미설정·안전정책 차단·토큰 절단·네트워크 장애 시
    규칙기반/결정적 템플릿으로 자동 전환하고 산출물에 `llm_used=false` 로 정직하게 표기한다.
    이 실패 경로 전부를 모의 HTTP 테스트로 검증한다(`tests/test_llm_paths.py`, 4/4).

### ⑤ 문서 작성

- **내용:** README(재현 절차·핵심 결과표), 구현내역서(`docs/IMPLEMENTATION.md` — 개발명세서

- **증빙 (문서 정확성을 사람 눈에 맡기지 않음):** `tools/check_doc_numbers.py` 가 문서에 적힌

  파이프라인을 다시 돌릴 때마다 실행하므로 문서와 산출물이 어긋난 채 제출될 수 없다.

### ⑥ 이미지 제작
- **도구:** Claude Code — 차트를 그리는 **코드**를 작성. **생성형 이미지 AI(DALL·E·Midjourney
  등)는 사용하지 않았다.**
- **내용:** SHAP 요약 플롯(`outputs/shap_summary.png`), 보정 곡선(`outputs/calibration.png`),
  Streamlit 대시보드 내 차트(점포수·매출 추이, SHAP 기여도 막대, EL 시나리오 막대).
- **왜 생성형 이미지 AI를 쓰지 않았나:** 본 산출물의 이미지는 전부 **실데이터에서 계산된
  도표**다. 생성 모델이 만든 그림은 수치 근거가 없어 금융 리스크 자료로 쓸 수 없다.
  모든 도표는 `outputs/` 의 수치 파일과 1:1로 대응하며 코드로 재생성된다.
- **반영 정도 판단:** 도표 자체는 코드가 계산해 그리므로 "AI가 이미지를 만들었다"고 보기 어렵고,
  그 코드를 Claude가 작성했으므로 **일부 반영**으로 기재하는 것이 정확하다.

### ⑦ 발표자료 제작
- **현 시점 미사용.** 발표자료를 제작하게 되면 사용 도구와 반영 정도를 이 절에 갱신한다.
- 발표자료에 넣을 근거 수치는 전부 `outputs/` 산출물에서 나오며, `README.md` 핵심 결과표가
  그대로 발표 슬라이드의 근거가 된다(수치 대조 자동화로 신청서·발표자료·코드가 어긋나지 않음).

## AI 활용 원칙 (심사 대응 문구)
- 원본 데이터 스냅샷 보존·seed 고정·버전 고정으로 **AI가 작성한 코드의 산출물을 사람이 재현·검증 가능**하게 설계.
- 라벨 규칙·임계값은 학습 전 git 커밋으로 고정하여 AI·인간 모두의 체리피킹을 차단.
- LLM 뉴스 신호는 모델 점수에 미투입(누출·재현성 원칙), 화면 표시 전용으로 분리.
- **AI가 쓴 코드를 AI가 검증하게 두지 않았다.** 결정적 자동검사(린트·문서수치 대조·명세 감사·
  단위 테스트·클론 재현)를 통과 조건으로 두고, 그 위에 반박 우선(refute-by-default) 적대적
  리뷰를 얹어 확정된 결함만 수정했다. 검증 방법과 결함 이력은 `docs/IMPLEMENTATION.md` 에 기록.
