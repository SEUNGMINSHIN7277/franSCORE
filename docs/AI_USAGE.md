## 단계별 상세 내역 (증빙 가능한 사실 기준)

### ① 아이디어 발굴
- **도구:** Claude (claude.ai 대화형)
- **내용:** '브랜드 단위 상관·집중 리스크'라는 프레임 정교화, 2025년 입상작과의 차별점 분석,
  평가기준 6개 항목별 득점 전략 수립, 기획서(FranSCORE_기획서_최종본.md) 공동 작성.
- **인간 기여:** 문제 인식(프랜차이즈 폐업 급증·자영업 대출 부실)과 주제 선정은 팀이 주도.

### ② 정보수집
- **도구:** Claude Code (모델: Claude Fable 5 / Claude Opus 5) — 병렬 웹 리서치 에이전트 9기(2차례)
- **내용:**
  - 1차: 공정위 오픈API 명세 조사(엔드포인트·파라미터·응답필드·인증방식·커버리지 실측),
    키 없는 파일데이터 대안 전수조사, franchise.ftc.go.kr 접근 메커니즘,
    뉴스 소스(Google News RSS·네이버 API) 비교 검증
  - 2차(빈틈 보강): 명세가 요구한 **직영점수·브랜드×지역 분포·브랜드 관리번호**의
    실제 제공 API를 라이브 호출로 확정 — 15125490·15125467·15125518 발굴 및 응답 필드 실측,
    가명·구간값 데이터셋(15143710/15143709) 배제 근거 확보,
    15125569 정보공개서가 별도 키를 요구함을 7가지 변형 호출로 확인
- **증빙:** 조사 결과가 `src/collect.py` SERVICES 정의·주석과 README 데이터 출처표에 반영됨.
  독립 API 간 가맹점수 일치율 98.9%로 조인 정합성 교차검증.

### ③ 데이터 분석
- **도구:** Claude Code (모델: Claude Fable 5) + LightGBM·SHAP·scikit-learn
- **내용:**
  - 공정위 실데이터 76,846행(브랜드×연도, 2017~2025 공시) 수집·정합·패널화
  - 엔티티 정합 규칙 설계(브랜드명 정규화·동명 분리·본부변경 추적), 생존성 진단
  - '악화 전환' 라벨 설계·검증(양성률 14.5%, 시점누출 자동 테스트), 완전 시간분할 백테스트,
    기준모형 3종 대비 성능 비교, 확률 보정, SHAP 요인 분해, 포트폴리오 상관손실 시나리오
- **증빙:** `outputs/` 지표 산출물 전체, `tests/test_sanity.py`.

### ④ 코드작성 및 디버깅
- **도구:** Claude Code (모델: Claude Fable 5 / Claude Opus 5; 멀티에이전트 병렬 구현·리뷰 워크플로)
- **내용:**
  - 전체 코드베이스(`src/` 13개 모듈, `run_pipeline.py`, `run_both_tracks.py`, `tests/` 2종,
    Streamlit 대시보드) 작성
  - 모듈 간 인터페이스 계약서(`docs/INTERFACES.md`) 기반 병렬 개발 + 자가 테스트
  - **적대적 코드리뷰 워크플로**(20 에이전트: 4차원 탐색 + 각 발견에 대한 반박 검증)로
    확정 결함 7건 발견·수정: 표본 선별 룩어헤드, 미검증 '양호' 라벨, logloss 조기종료,
    보정확률 동률 붕괴, 대시보드 스트레스 방향 반전, 등급 컷 왜곡, 0점포 유령 라벨
  - LLM 실경로 모의 API 테스트 작성 중 **오도 로그 결함 추가 발견·수정**
- **비고:** 프로토타입 내부의 LLM 기능(뉴스 신호 구조화·심사메모 생성·RAG 근거 인용)은
  Anthropic API(claude-opus-5)를 호출하도록 구현 — 즉 **산출물 자체에도 Claude가 런타임
  구성요소로 포함**된다. 키 미설정 환경에서도 실제 LLM 코드 경로를 모의 API로 검증했다.

## AI 활용 원칙 (심사 대응 문구)
- 원본 데이터 스냅샷 보존·seed 고정·버전 고정으로 **AI가 작성한 코드의 산출물을 사람이 재현·검증 가능**하게 설계.
- 라벨 규칙·임계값은 학습 전 git 커밋으로 고정하여 AI·인간 모두의 체리피킹을 차단.
- LLM 뉴스 신호는 모델 점수에 미투입(누출·재현성 원칙), 화면 표시 전용으로 분리.
