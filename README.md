# FranSCORE

**프랜차이즈 브랜드 여신 포트폴리오 집중·상관 리스크 관리 — KB 제8회 AI Challenge 프로토타입**

> 같은 프랜차이즈 브랜드에 묶인 여신은 '브랜드'라는 공통 요인으로 상관된다.
> **이 전제를 주장이 아니라 실데이터로 측정했다 — 브랜드 내부 자산상관 ρ=0.416(바젤 기업여신
> 가정의 1.7~3.5배)인 반면 브랜드 간은 0.005. 위험은 경기가 아니라 브랜드에 있다.
> 차주를 독립으로 보면 비예상손실을 5.31배 과소추정한다. (아래 ⓪)**
> FranSCORE는 공정위 공개 공시로 **브랜드의 구조악화 전환을 예측(LightGBM)·설명(SHAP)** 하고,
> 이를 은행의 **브랜드별 여신 집중도와 결합해 상관 손실 위험을 원화로 정량화**하는 2선 리스크 관리 도구다.

### ⓪ 전제 검증 — "브랜드가 공통 위험요인"을 **주장하지 않고 측정**했다

이 도구는 *"같은 브랜드에 묶인 여신은 브랜드라는 공통 요인으로 상관된다"* 는 전제 위에 서 있다.
전제가 거짓이면 브랜드 단위 관리는 불필요하다. 그래서 먼저 측정했다 (`src/correlation.py`).

**식별 전략:** 한 브랜드의 점포는 여러 시도(市道)에 흩어져 있고, 시도마다 상권·지역경기·임대료가
다르다. 점포 감소가 지역별로 **독립**이면 입지 요인이고, 여러 지역에서 **동시에** 일어나면
브랜드 요인이다. 독립 가정을 넘어서는 동시성의 초과분이 곧 브랜드 공통요인이다.

| 통제 수준 | 자산상관 ρ | 무엇을 걷어냈나 |
|---|---|---|
| 통제 없음 | 0.418 | (거시+업종+브랜드 혼재) |
| 연도 통제 | 0.417 | 코로나 등 **거시충격** 제거 |
| **연도+업종 통제** | **0.416** | **브랜드 고유 상관** |

→ 거시·업종을 걷어내도 상관이 **거의 그대로**다. "그냥 코로나 아니냐"는 반론이 수치로 기각된다.
브랜드 자체가 공통 요인이다.

- **브랜드 고유 자산상관 ρ = 0.416** (95% CI **[0.382, 0.438]**, 브랜드 블록 부트스트랩)
  — 바젤 IRB가 기업여신에 **가정**하는 자산상관 12~24%의 **1.7~3.5배**
- 한 브랜드의 **모든 지역이 동시에** 감소한 사례: 실측 **4.31%** vs 지역 독립 가정 0.200% → **21.6배**
- 표본: 브랜드-연도 6,328 · 브랜드 1,606 · 지역쌍 349,089 (2017~2024)

**브랜드 *간*에는 상관이 거의 없다 — ρ_B = 0.005** [0.000, 0.009]

브랜드 단위 악화율의 연도 간 변동에서 역산한 값이다(부도율 시계열 적률법, 8개 연도).
연도별 악화율이 0.53~0.62로 매우 안정적이라 **거시 공통요인은 사실상 검출되지 않는다.**

> 이 대비가 핵심이다. 위험은 **경기(거시)에 있지 않고 브랜드에 있다.**
> 그래서 처방도 "경기 대응"이 아니라 **"브랜드 단위 집중 관리"** 가 정확히 옳다.

**브랜드를 무시한 대가** — 차주(가맹점) 단위 **2단계 요인 모형** 몬테카를로 20만 회

은행 여신은 브랜드 법인이 아니라 **개별 가맹점주**에게 나간다. 그래서 차주를 개별 노드로 두고
브랜드를 중간 계층으로 갖는 모형으로 계산한다 (예시 포트폴리오 = 60개 브랜드 **9,180 차주**):

  `X_ij = √ρ_B·Z(거시) + √(ρ_W−ρ_B)·Y_i(브랜드 i) + √(1−ρ_W)·ε_ij(가맹점)`

| 신뢰수준 | 차주 독립 가정 | 브랜드 상관 반영 | 과소추정 |
|---|---|---|---|
| 95% | 14.5억 | 19.0억 | +4.5억 (+31.1%) |
| **99%** | **14.9억** | **21.7억** | **+6.8억 (+45.6%)** |
| 99.9% | 15.5억 | 25.3억 | +9.9억 (+64.0%) |

> 차주 9,180명을 서로 무관한 소상공인으로 보면 비예상손실(자본 소요분)은 1.6억이지만,
> 브랜드로 묶여 있다는 사실을 반영하면 **8.4억 — 5.31배**다.
> 대수의 법칙이 작동하지 않는 이유가 바로 '브랜드'이고, 이것이 이 도구가 필요한 이유다.

<details><summary>왜 ρ_W 를 그대로 포트폴리오에 넣지 않았나 (층위 이중계상 방지)</summary>

ρ_W = 0.416은 **한 브랜드 안에서 지역끼리** 얼마나 함께 움직이는지다. 브랜드 1개를 채무자
1행으로 집계한 뒤 이 값을 브랜드 *사이* 상관으로 쓰면 이중계상이 된다 — 집계 과정에서
브랜드 내부 상관은 이미 ρ=1로 소진되기 때문이다. 그래서 ρ_W(브랜드 내부)와 ρ_B(브랜드 간)를
따로 측정해 2단계 모형의 제자리에 각각 넣었다. 이 수정으로 헤드라인 수치는 **줄었지만**
(수정 전 대비 크게 낮아졌지만) 층위가 맞다. 자체 감사에서 지적된 사항을 그대로 반영한 결과다.
</details>

<details><summary>이 수치를 읽을 때의 한계 (클릭)</summary>

- 관측 단위는 **'지역 내 가맹점 수 감소'** 이지 차주의 부도가 아니다. 따라서 ρ는 부도상관의
  직접 추정치가 아니라 **대리지표**다. 비교 대상인 바젤 자산상관도 관측값이 아니라 규제 가정값이다.
- 손실 시뮬레이션의 exposure는 **공정위 공시 창업비용에서 유도한 추정치**다(§④ 참조).
  절대 금액보다 **독립 가정 대비 배수**가 이 표의 메시지이며, 배수는 exposure 스케일에 불변이다.
- 추정기 자체의 정확성은 정답을 아는 합성 데이터로 검증한다
  (`tests/test_sanity.py::correlation_math` — 역산 왕복 오차 <1e-3, 독립 데이터에서 ρ≈0,
  심어둔 ρ=0.30 복원, 거시충격만 있는 데이터에서 층화가 0.142→0.003으로 제거).
</details>

### ① 명세 규정 평가 — 단일 시간분할 test 2023 (n=740, base rate 8.1%)

| 모형 | Lift@10% | Precision@10% | PR-AUC | ROC-AUC | Brier |
|---|---|---|---|---|---|
| ① 전년 상태 유지 (persistence) | 1.500 | 0.122 | 0.116 | 0.545 | 0.096 |
| ② 계약종료율 단일변수 | 2.167 | 0.176 | 0.141 | 0.637 | 0.232 |
| ③ 로지스틱 회귀 | 2.000 | 0.162 | 0.171 | 0.736 | 0.197 |
| **LightGBM (주모형)** | **2.500** | **0.203** | **0.186** | **0.749** | 0.128 |
| LightGBM (보정) | 2.500 | 0.203 | 0.186 | 0.749 | **0.075** |

→ **명세 M3 DoD 통과**: LightGBM Lift@10% **2.500 > 기준모형 최고치 2.167**. PR-AUC·ROC-AUC도 최우수.

**Brier(보정품질)는 공정하게 비교해야 한다 — 자체 감사 지적 반영.** 위 표의 기준모형 Brier는
*미보정* 원점수 기준이라 LightGBM(보정)과 나란히 놓으면 불공정하다. 기준모형 3종에도 **완전히
동일한 isotonic 보정**(같은 valid, 같은 PD 상·하한)을 적용해 다시 비교한 결과:

| 모형 (동일 보정 적용) | Brier |
|---|---|
| **LightGBM** | **0.075** |
| 로지스틱 | 0.077 |
| persistence | 0.078 |
| 계약종료율 단일변수 | 0.078 |

LightGBM이 여전히 최우수지만 **차이는 0.002~0.003으로 미미하다.** 보정을 붙이면 어떤 점수든
Brier는 비슷해진다는 뜻이므로, "Brier 최우수"를 다변량 모형의 주된 실익으로 내세우지 않는다.
실익은 **순위 성능(Lift·PR-AUC)과 SHAP 요인 분해**에 있다. (`outputs/metrics.csv` 에 `*_calibrated` 행으로 전부 공개)

### ② 검정력 보강 — 워크포워드 확장창 3-fold (OOS n=2,063, 양성 191)

단일 연도 test는 양성이 60건뿐이라 통계적 검정력이 부족하다. 이를 **숨기지 않고** 확장창
워크포워드(2021·2022·2023 각각 자기 시점 이전만으로 재학습)로 표본을 3배로 늘려 재검정했다.

**집계는 fold 안에서 한다** (주 지표 `macro_avg_folds` = fold별 Lift@10%의 평균). fold마다
모형을 재학습하므로 출력 확률의 스케일이 fold마다 다르고, 원점수를 전역으로 한 줄 세워
상위 10%를 뽑으면 **재학습 모형이 부당하게 불리해진다** — 실측으로 LightGBM의 2023 fold는
행의 35.9%를 차지하는데 전역 상위 10%의 4.4%만 차지했다(편향배수 0.12).
운영 의미로도 "매년 상위 10%를 점검한다"가 맞는 정의다. 세 가지 집계를 모두 공개한다
(`outputs/walkforward_metrics.csv`, 편향 진단은 `walkforward_pool_bias.csv`).

| 모형 | fold 평균 Lift@10% | fold별 (2021 / 2022 / 2023) |
|---|---|---|
| ① persistence | 1.688 | 1.811 / 1.751 / 1.500 |
| ② 계약종료율 단일변수 | 2.403 | 2.415 / 2.627 / 2.167 |
| ③ 로지스틱 회귀 | 2.472 | 2.415 / 3.002 / 2.000 |
| **LightGBM** | **2.456** | 2.617 / 2.252 / 2.500 |

| 비교 | Lift 차이 | 95% CI (연도블록 부트스트랩) | 승률 | 판정 |
|---|---|---|---|---|
| LightGBM − persistence | **+0.775** | **[0.602, 0.937]** | 100% | **유의하게 우위** |
| LightGBM − 단일변수 | +0.063 | [-0.183, 0.290] | 78% | 통계적 동등 |
| LightGBM − 로지스틱 | +0.001 | [-0.433, 0.403] | 40% | 통계적 동등 |

> **정직한 주장 범위:** LightGBM은 기획서가 우려한 **자기상관(persistence) 함정을 통계적으로
> 유의하게 극복**한다. 반면 잘 설계된 단일변수·로지스틱 기준모형과는 **동등**하며, "압도적 우위"를
> 주장하지 않는다. 연도 블록이 3개뿐이라 CI는 보수적 근사이며 정밀한 p-값으로 읽어선 안 된다.
> 다변량 모형의 실익은 순위 성능과 SHAP 요인 분해에 있다(보정 Brier는 공정 비교 시 차이가 미미 — 위 ① 참조).

**불리한 결과도 함께 공개한다 (침묵에 의한 체리피킹 방지).**

| 산출물 | 결과 | 해석 |
|---|---|---|
| `newbrand_split.csv` | 기존 브랜드에서 로지스틱 3.014 > LGBM 1.884, 신규 브랜드에서 persistence 2.131 > LGBM 1.522 | **부분표본 양쪽 모두에서 LGBM이 1위가 아니다.** 전체에서 1위인 것은 두 부분표본의 기저율 차이(5.1% vs 15.6%) 때문이며, 부분표본별 최적 모형이 다르다는 뜻이다 |
| `ablation.csv` | 수준 피처 7개만으로 Lift@10 = 2.500 (전체 35개와 동일) | **추가한 피처 28개가 Lift@10을 더 올리지 못했다.** ROC-AUC는 0.718→0.749로 개선되므로 전 구간 판별력에는 기여하지만, 상위 10% 선별에는 수준 피처가 대부분을 설명한다 |

두 결과 모두 이 프로젝트에 불리하지만 산출물에 그대로 남기고 여기에 적는다. 소표본(test 양성 60건)
에서 부분표본 지표는 변동이 크다는 점도 함께 밝힌다.

### ②-2 AI(LLM)가 규칙기반보다 나은가 — **측정했다**

"LLM을 붙였다"는 것만으로는 근거가 아니다. 정답셋을 만들어 같은 입력·같은 지표로 채점했다
(`data/eval/news_gold.jsonl`, 생성기 `tools/build_news_gold.py`, 실행 `--step eval_llm`).

| 구간 | 방식 | 정확도 | macro-F1 | 위험탐지 F1 | 위험 재현율 |
|---|---|---|---|---|---|
| 실수집 41건 | 규칙기반 | 0.488 | 0.381 | 0.500 | — |
| 실수집 41건 | **Gemini** | **1.000** | **1.000** | **1.000** | 1.000 |
| 프로브 18건 | 규칙기반 | 0.444 | 0.432 | 0.636 | — |
| 프로브 18건 | **Gemini** | **0.889** | **0.911** | **0.917** | **1.000** |
| 전체 59건 | 규칙기반 | 0.475 | 0.498 | 0.615 | — |
| 전체 59건 | **Gemini** | **0.966** | **0.945** | **0.933** | **1.000** |

- 정답셋은 **실제 수집된 기사 제목**에 사람이 판정 기준을 적용해 라벨을 붙인 것이다.
  규칙기반이 붙인 라벨을 정답으로 쓰면 규칙이 100점이 되는 순환논증이므로 그렇게 하지 않았다.
- 실수집분에는 본부분쟁·재무이슈·집단폐점 사례가 **0건**이라 그 클래스의 재현율을 잴 수 없다.
  그래서 합성 프로브 18건을 별도로 두고 **결과를 분리 보고**한다(합쳐서 뭉개지 않는다).
  프로브는 규칙이 실패하는 두 방향을 모두 담는다 — *키워드는 있으나 위험 아님*(예: "상생협약
  체결하며 갈등 봉합"), *위험이나 키워드 없음*(예: "전국 매장 절반이 간판을 내렸다").
- 이 평가 과정에서 **분류 체계의 공백**이 드러났다: 실측 기사 "탕후루 유행 꺾이더니 1년 새
  매출 92% 급감"을 규칙·LLM **양쪽 모두** '기타'로 흘려보내고 있었다. 프랜차이즈 여신에서
  가장 중요한 위험 중 하나인데 5분류에 자리가 없었던 것이다 → **'수요급감' 유형을 신설**했다.
  평가셋을 만들지 않았다면 발견하지 못했을 결함이다.
- 표본이 수십 건이므로 소수점을 유의미한 차이로 읽지 말 것. 오분류 31건 전수는
  `outputs/llm_eval_errors.csv` 에 남겨 사람이 직접 확인할 수 있게 했다.
- **측정한 모델을 그대로 운영에 쓴다** (`gemini-2.5-flash`).

**심사메모 환각 자동 검증.** "입력 근거만 인용하라"는 프롬프트 지시는 보증이 아니다.
생성된 메모의 모든 수치를 입력 context와 대조해(반올림·백분율 변환 허용) 근거 없는 수치가
있으면 **메모 본문에 경고를 붙인다**. 회귀 테스트로 지어낸 수치(412.7%, -18.3%)를 실제로
잡아내는 것을 확인한다(`tests/test_llm_paths.py`).

### ③ 표본 트랙 2종 — 둘 다 공개 (체리피킹 방지)

명세 §11 플랜B가 허용하는 확장 표본(전 업종·점포 20+)도 **사전 선언 후 함께** 실행했다.
결과가 좋은 쪽만 고르지 않는다.

| 트랙 | 라벨 표본 | 단일분할 LightGBM Lift | 워크포워드 fold평균 LightGBM Lift |
|---|---|---|---|
| **기본**(명세: 외식·30+) | 3,635 | **2.500** (최우수) | 2.456 (로지스틱 2.472와 동등) |
| 확장(플랜B: 전업종·20+) | 6,406 | 2.082 (로지스틱 2.263에 열위) | 1.993 (로지스틱 2.300에 **열위**) |

→ 업종 혼합은 트리 모형에 불리했다. 명세 표본(외식 특화)이 더 적합하다는 실측 근거.

### ④ 포트폴리오 상관 손실 (합성 예시 여신 — 방법론 실증)

> 총 여신 666억원 · LGD 45% 기준 1년 예상손실 **13.3억원**(2.00%) · 위험 상위 10% 동시 악화
> 스트레스 시 **15.4억원** · 상위 10개 브랜드 집중도 62.2% · HHI 0.068

PD는 여신 실무 관행대로 **하한 0.03%(바젤 IRB) · 상한 99%** 로 클립한다. isotonic 보정이 계단함수라
양 끝이 검증표본 경험률로 포화되어 실측에서 "1년 악화확률 100%"가 나왔기 때문이다(단조 변환이라
순위 기반 지표는 불변, 과신만 억제).

## 빠른 시작 (재현 절차)

```bash
git clone <repo> franscore && cd franscore
pip install -r requirements.txt          # 버전 고정 (Python 3.13 기준)

# 전체 파이프라인 (수집→패널→피처→라벨→학습→평가→포트폴리오→뉴스)
python run_pipeline.py --step all

# 두 표본 트랙 + 워크포워드 검증 전부 (제출 근거 재생성)
python run_both_tracks.py

# RAG 코퍼스·색인 구축 (심사메모 근거 검색)
python -m src.rag

# 대시보드
streamlit run src/app.py

# 테스트
python -m tests.test_sanity        # 5/5 (라벨규칙·시점누출·시간분할·스키마·포트폴리오)
python -m tests.test_llm_paths     # 4/4 (LLM 클라이언트·실경로·RAG — 모의 HTTP, 키 불필요)

# 린트 (규칙·버전 고정 — ruff.toml / requirements-dev.txt)
pip install -r requirements-dev.txt && python -m ruff check .    # 기대: All checks passed!
```

**재현성 실측 확인:** 새 클론에서 `data/raw` 스냅샷만으로 API 호출 없이 실행 → 라벨 표본 3,635행,
양성률 9.2%, LightGBM Lift 2.500이 **정확히 동일 재현됨**.
문서에 적힌 수치가 실제 산출물과 일치하는지는 `python tools/check_doc_numbers.py` 가 매번 대조한다.

- `data/raw/` 스냅샷 포함(대용량은 gzip) → **API 키 없이 전체 지표 재현 가능**.
  수집 재실행 시에만 `DATA_GO_KR_KEY` 필요 (data.go.kr 개발계정 자동승인).
- LLM 기능(뉴스 신호 구조화·심사메모)은 `GEMINI_API_KEY` 설정 시
  **Google Gemini(`gemini-3.6-flash`)** 로 동작 — `python check_keys.py --llm` 으로 즉시 진단 가능.
  없으면 규칙기반 폴백으로 자동 전환(화면·로그에 `llm_used=false`, 폴백 건수까지 명시).
  **키 없이도 LLM 실제 코드 경로는 모의 HTTP 테스트로 검증됨**(`tests/test_llm_paths.py`).
- 합성 데이터 스모크: `python run_pipeline.py --step all --demo` (산출물 `outputs/_smoke/` 격리)

## 정직성·재현성 장치

1. **시점 누출 금지** — 연도 t 피처는 t 이하만 사용. 윈저라이즈·업종분위수·보정기·복잡도 선택 모두
   해당 시점 또는 valid에서만. t+1 이후 전체 교란 후 피처 bit-exact 불변을 자동 검증.
   전수 점검표: **[docs/LEAKAGE_CHECKLIST.md](docs/LEAKAGE_CHECKLIST.md)** (명세 §4.2)
2. **실시간 표본 선별** — 표본 편입도 t까지의 누적 정보만 사용(초기 구현의 룩어헤드 결함을
   적대적 리뷰로 발견해 수정, 이력 문서화).
3. **라벨 동결** — 규칙·임계값을 `config.yaml`에 학습 전 고정, 최초 git 커밋으로 증빙.
4. **과튜닝 금지** — 그리드서치 없음. 3개 사전 선언 복잡도 후보를 **valid AUC로만** 선택, test 미사용.
5. **체리피킹 금지** — 두 표본 트랙을 사전 선언하고 **둘 다 공개**. 부트스트랩 CI로 우위 주장의
   불확실성까지 공개(유의하지 않은 비교는 "동등"으로 명시).
6. **합성 명시** — 여신 익스포저는 방법론 실증용 합성 예시. 모든 화면·산출물·메모에 상시 표기.
7. **LLM 정직 표기** — 실제 LLM 추출 건수와 규칙 폴백 건수를 분리 로깅(의도가 아닌 결과 기준).
